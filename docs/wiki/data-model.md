# Data model

Every file and record Studio reads or writes, from the code on `main` (6636327, 2026-11-10). Paths in code are under `tool/`. How the parts fit: `architecture.md`.

## The hand-off file (the contract with BRIMM Ops)

`*.brimm-ops.json`, written last into the episode's `final/` folder and dropped by hand on the BRIMM Ops page. JSON indented by two spaces, a line break at the end (`handoffText`). `format` is always `"brimm-video hand-off"`. brimm-operations keeps copies of the fixtures in `tool/tests/fixtures/`; `contract.test.js` pins their hashes. Change the writer, its check or a fixture only together with brimm-operations.

### Version 2 (`tool/handoff-v2.js`: `buildHandoffV2`, checked by `handoffFaultV2`)

Keys in this order, and no others: the check refuses any key the contract does not name.

| Key | Shape |
|---|---|
| `format`, `version` (2), `revision` | `revision`: a whole number from 1, rising across versions and formats |
| `made` | local time with its offset, `YYYY-MM-DDTHH:MM:SS±HH:MM` |
| `madeOn`, `madeBy` | the Mac's name; `brimm-video <commit>` |
| `video` | `{ id, kind, name, recorded, recordedFrom }`: `id` `e-YYYYMMDD-<6 hex>` (the first version's id, kept by later versions); `kind` `finished`, `raw`, `session` or `short video` (a record kept as `episode` is written `raw`); `recorded` a day; `recordedFrom` `video` or `import`. No title: titles live on the page. |
| `main` | not for a session. `{ file, seconds, srt, onPicture? }`: the file's name in `final/`, its length, its captions. `onPicture` (the words drawn on the picture, in order) only for a raw or short video, and left out when empty. |
| `suggestions` | a finished or raw video's only, left out when none: `[{ n, start, end, stretches: [{start, end}], first, last, why, point }]`, on the final main video's clock, to the hundredth of a second. A finished video's suggestion is one stretch. A suggestion is kept only when 70 in 100 of its words survive the cut (`suggestionsOnClock`, `KEPT_IN_100`). |
| `reels` | not for a short video. `[{ n, title, file, seconds, inMain?, srt, fromSuggestion }]`; `title` may be empty but must be there; `fromSuggestion` is the suggestion's number (and then equals `n`) or `null` for a Reel from times she gave (a fresh number). A session's Reel has no `inMain` and carries `clientAgreed` (the day the client's agreement was noted, never who), and its `fromSuggestion` is `null`. |
| `session` | `null` unless a session. A session: `{ principles, recurringPrinciples, reelsToFilm }`, only what Sallie approved. Principle: `{ n, name, category?, description?, steps?, red_flags?, green_flags?, decision_criteria?, example_application?, verbatim_key_phrases? }`; fields the name check took out are left out; `source_context` is never written. Recurring: `{ n, text }`. Reel idea: `{ n, idea, words?, why?, principle }` (`principle` a principle's number or `null`). A session's hand-off has no `main` and no transcript. |

### Version 1 (`tool/handoff.js`: `buildHandoff`, `handoffFault`; still read by the page)

`{ format, version: 1, revision, made, madeOn, madeBy, episode: { id, kind: "episode"|"short video", name, recorded, recordedFrom, title }, main: { file, seconds, srt }, reels: [{ n, title, file, seconds, inMain?, srt }] }`. An episode needs its approved title; a short video has no Reels. `inMain` is where a Reel's words fall in the main video (90 in 100 of them found in order, within 1.5 times the Reel's length).

`normalWords` (in `handoff.js`) also makes the words that `versions.js` fingerprints: change it and every stored fingerprint matches nothing.

## The Mac's settings

`~/Library/Application Support/BRIMM Video/settings.json` (`settings.js`; written `.writing` then renamed, unknown fields kept; `install.sh --machine` calls `settings.js write`).

- Required: `version: 1`, `machine` (the Mac's name, at most 40 characters, file-safe), `root` (Dropbox's `BRIMM Video`), `checkout` (where `tool/` is).
- Optional: `import` (`light`), `readings`, `handoffVersion` (1 or 2), `drop` (`Drop` or `Unedited Video`), `dropPath` (the Mac's own drop folder: the Mac is "local"), `exportsPath` (else `~/Downloads`), `sessionTeachings` (on for 90 days), `lock` (`strict` or `open`), `web` (`held` or `open`), `zoomFolder`, `proxyPort`, `studioNode`, `studioAllow`, `userDeny`, `app` (`hyperframes` or `off`), `appHandover`.

Beside it, each written `.writing` then renamed: `written.json` (the last record each episode was written at, to see Dropbox undo a write), `seen.json`, `pending/` (late checks owed: the import's own, `record/`, `final/`, `original/`), `importing/` (status files, local Macs), `access.json`, `guide.json` (her guide's done steps, by hand-off), `update-check.json`, `lock-cache.json` (the guard's cached lock check, 30 s), `progress/`, `receipts/`, `held/`. A session's words for one chat: `~/Library/Application Support/BRIMM Video Words/<chatId>/`, cleared after a day. Logs: `~/Library/Logs/brimm-video.log`, `brimm-video-claude-check.log`.

`~/Library/Application Support/BRIMM Video/app-version.json` (`app-version.js`; written whole, temp then rename): `{ version, build, at }`, the HyperFrames app's version last seen (`CFBundleShortVersionString`, `CFBundleVersion` of the first copy, `/Applications` before `~/Applications`). The first one seen is not a change; a later different one is said once.

Environment: `BRIMM_VIDEO_HOME` (Studio's home instead of `HOME`, absolute only; programs it starts get the real `HOME`), `BRIMM_WHISPER_MODEL`; `install.sh` only: `BRIMM_AGENT_PATH`, `BRIMM_HOMEBREW_DIRS`, `BRIMM_CLAUDE`. No code reads `BRIMM_DB`: read the root from settings.json.

## Folders

**Dropbox `BRIMM Video/`** (the settings' `root`). Nothing there is written in place, renamed or moved: files are made whole in a run folder, then cloned in with `/bin/cp -c` (`dropbox.js`), and checked again 15 minutes later (the late check).

- `Episodes/<YYYY-MM-DD> <video name> (<Mac>)/` (`names.js episodeFolderName`, `-2` on a clash): `record/NNNN.json`, `final/` (the finished files and the hand-off), `history/`, `Original files/` (the recordings, after the hand-off), `previews/reel-<n>.mp4`, a plan's `video guide.md`, `shot list.md` and `teleprompter.txt`. An episode from a Dropbox drop also keeps its video and transcript files here.
- `Episodes/.importing/`: import status files for a Mac with a Dropbox drop.
- `Drop/<Mac>/` or `Unedited Video/<Mac>/`: a Dropbox drop folder, marked `.brimm-watched-by`.
- `References/` (pictures she adds; Studio only reads them), `Assets/Logos/`.
- The HyperFrames app's own projects folder (`HyperFrames`) is beside these; no code reads it.

**`~/BRIMM Video Work/`** (local, never in Dropbox):

- `Drop/`: the default local drop folder.
- `.runs/`: run scratch; the import lock `brimm-transcribe-<hash>.lock`.
- `.toolchain/hyperframes-<version>/`: the pinned HyperFrames CLI.
- `<episode folder>/`: `video/` (on a local Mac, the episode's own files: the recording, its `.srt`, `.words.json`, `.cut-plan.json`, `reels.json`; `.import.json`, `.put.json`, `history/`), `working copy/<bytes>-<mtimeMs>.mp4` with a facts `.json` (Reels, footage and voice have their own names; a Reel Kit edit's copy of 4K is made as `<key>-4k.mp4` for the main video and `reel-<n>-<key>-4k.mp4` for a Reel, which replaces only that Reel's other copies of 4K, and is then moved into its project), one folder per HyperFrames project and per Reel Kit edit, `renders/`, `put back/`, and the locks and markers below.
- `Saved test recordings/`: test originals kept by hand; no code uses it.

## The episode record

`Episodes/<folder>/record/NNNN.json` (`episode.js`). Never overwritten: each change is a new file with the next number, and the record is the highest-numbered file that reads whole. `writeEpisode` refuses a stale write (`NEWER`, `CONFLICTED`, `CHANGED`); a Dropbox conflicted copy stops everything.

- **Id:** `e-YYYYMMDD-<6 hex>`; the short id is the 6 hex (`fbb80c`).
- **Layouts** (`version`): 1 base; 2 layers; 3 the switch (kinds, answer, reading, session); 4 `app`; 5 `planned`, `partOf`; 6 `local`. A Mac on older code reads a newer layout as `newer` and never writes it.
- **Base:** `id`, `rev` (the file's number), `writer {commit, on}`, `kind` (`episode`, `short video`, `finished`, `raw`, `session`, or `null` while unanswered, a part or a plan), `video {file, bytes, seconds, recorded, recordedFrom, sound?}`, `imported`, `name {text, placeholder}`, `title {text, from, approved}`, `editing`, `released`, `archived`, `files`, `spellings` (`[heard, meant]` pairs), `main {cuts, texts, graphics, …}`, `brand`, `reels [{n, status: candidate|picked|dropped|finished, from, to, title, …}]`, `finished {revision, at, on}`.
- **Layout 3:** `answer {state: needs your answer|answered|not for brimm-video|part|planned, guess, came: camera|phone|zoom|sound, by, on, at, private}`, `label`, `fingerprint`, `versionOf`, `session {marked, teachings, cleared, decided, edits, agreed: [{n, at}], …}`, `reading {kind, model, at, on, account, outcome, …}`, `offers {spellings, answered}`, `principles` (the teachings file's name).
- **Layout 4:** `app {toolchain, projects: [{key: main|reel N|clip N, name, madeAt, on, from, workingCopy, opened, handover, fromSuggestion, state: made|opened|exported|finished|kept for an earlier kind}]}`. A Reel Kit edit's entry (`reel-kit-project.js` `entryOf`) has the same shape, with `maker: "reel-kit"`, `mode` (`hifi`, `lofi` or `showcase`) and `version` (from 1, Decision 11), `from` the recording and `workingCopy` its copy of 4K; its own progress is in its project's `studio.json`, never in the record. A HyperFrames project has no `maker`. The entry is written by the queued job of `reelkit start` once `scaffold` has made the project (`reel-kit-commands.js`; plan Task 11), with the record read again first and `app.toolchain` kept (HyperFrames' pin when there was no `app`). Nothing that makes, adopts or opens a HyperFrames project takes it for its own (`app.js` `byReelKit`: `isMain`, `projectOnAnotherMac`, `app-reel.js` `madeInApp` and its open, `edit.js` `clipWords` and `refsProject`), and `app` refuses a part that has one in one line.
- **Layout 5:** `planned {route: script|explainer, title, voice: sallie|heygen|null, cues, shots, lines, filmed, consent, project}` (a plan has `video: null`); `partOf {id, as: talking|screen|b-roll|voiceover, shot, client}`.
- **Layout 6:** `local {on: <Mac>, original}`. Only `record/`, `final/`, `history/`, `Original files/` and a plan's three files are in Dropbox; everything else stays on the Mac named in `on` (`where.js filePlace`).
- **Kinds** (`kinds.js`): the import guesses `clip`, `raw` or `finished`; it came from `zoom`, `sound`, `phone` or `camera`. Upright, square or under 90 seconds is a `short video`.

Import status files (`importing.js`): `"<video> (<Mac>) <importId> <n>.json"`, `{version, machine, pid, video, bytes, seconds, step, at, failed?, problem?, …}`, stale after 10 minutes.

## Transcripts and readings

- From the import, named after the video: `.srt`, `.transcript.txt`, `.words.json` (`[{w, start, end}]` in seconds), `.cut-plan.json` (`phrases`, `ranges` with kinds `keep`, `retake`, `false start`, `cue`), `.cut-plan.txt`, `.rough-cut.srt`, `.rough-cut.transcript.txt`; after a raw video's reading, `.edit-notes.txt`.
- `reels.json` (`reel-candidates.js`): `{format: "brimm-video reels", version, candidates: [{n, ranges [{start, end, crop?}], title, reason, why, point, phrases}]}`.
- A session's teachings (`teachings.js`): `<name>.principles.json` (`format: "brimm-video teachings"`: `principles`, `recurringPrinciples`, `reelIdeas`), with `.principles.txt` and `.reel-ideas.txt`. Other speakers' names are taken out (`sessions.js`). Her choices live in the record's `session.decided` and `session.edits`.
- The reading (`reading.js`): one Claude call, its result in `record.reading` and `record.offers.spellings`; the earlier cut plan is set aside in `history/`.

## The HyperFrames project Studio writes

`~/BRIMM Video Work/<episode folder>/<project>/` (`project.js`), written whole in a run folder and moved into place, the working copy last:

- `index.html`, `meta.json`, `hyperframes.json`, `package.json`, `transcript.json` (`[{text, start, end, id}]`, spelled), `CLAUDE.md` and `AGENTS.md` (the same notes), `vendor/gsap.min.js`, `assets/fonts/`, `assets/logos/`, `media/recording.mp4` (or `media/voiceover.m4a` for an explainer in her voice; footage as `media/b-roll-N.mp4`), `node_modules/.bin/hyperframes` (a link to the pinned CLI).
- `.claude/settings.json` (`hyperframes.js settingsFor`): `permissions.deny` (the pin's denied commands; a clip adds the web tools) and `env` (HyperFrames' telemetry, skills, update and install checks off; `/feedback` and the survey off; the HeyGen key variables blanked). The app ignores this file; the command line honours it.
- `brimm/`: `facts.json`, `cut-suggestions.json` and `reel-suggestions.json` (main only), `graphic-cues.json` (kinds `graphic`, `words`, `b-roll`, `screen`), `face-track.json` (a Reel), `spellings.json` (the house `brim` → `BRIMM` first), `brand.md`, `teleprompter.txt` (an explainer), `references/`.

What the app writes and Studio reads back:

- `.hyperframes/app-history.jsonl` (`app-history.js`): one JSON a line, `{at, engine, asked, did, files}`; only the last 1 MB is read. `history --json` through the pinned CLI gives the versions.
- `.hyperframes/transcripts/`: the app's own cloud transcripts (Studio does not use them).
- `renders/<project>_<YYYY-MM-DD>_<HH-MM-SS>.meta.json` (with `exportedTo`) beside each export; the exports themselves land in Downloads or the Mac's exports folder (`mp4`, `mov`, `m4v` taken).
- `index.html`: where the recording sits on the timeline (`data-start`, `data-duration`, `data-playback-start`/`data-media-start`, `data-playback-rate`; `on-timeline.js`).

## A Reel Kit project Studio makes

`~/BRIMM Video Work/<episode folder>/<projectName of the part> Reel Kit v<n>/` (`reel-kit-project.js` `scaffold`, a step of the queued job, under the Mac-wide worker lock; `startWhy`, before it is queued, refuses a title `new.py` can't take and needs `held` said), beside the episode's HyperFrames projects, never in Dropbox or a drop folder. A later version of the same part is a new folder; the earlier one stays as it is.

- `source/clip.mp4` and `source/clip.json` (its facts): the part's copy of 4K, made in `working copy/` (`workcopy.js` `makeWorkCopy` with `fourK`, and a Reel's own times from the record, `reels[].from`/`to`: Decision 3) and moved in by renaming (facts first, video last), as a HyperFrames project takes its working copy in. It is the project's own: a later copy of 1080 and `free` take only what is in `working copy/`. A copy an earlier run of the same edit moved in is kept; anything else at `clip.mp4` is never written over.
- `studio.json` (`stateFile`; written whole by Studio, a file of its own beside it then renamed, never by the worker; read by `readState` with no link followed, no pipe waited on and at most 1 MB): `{slug, key, mode, version, title, name, madeAt}`, and the job's own (`reel-kit-worker.js` `runJob`, plan Task 10), which `scaffold` keeps: `state` (`queued`, `working`, `stopped`, `storyboard`, `ready`, `failed`, then `rendered`), `job` (`edit`, `revise`, `finalize`, `style`), `step` (one of the job's `JOBS` steps), `pid` (the run that holds the job), `worker` and `workerStart` (the `claude` process's pid and its `ps` start time, while it runs: a `working` job whose runner died but whose `claude` still runs reads working), `session` (Claude Code's session, for a resume), `needs` (`[{beat, text}]`, Reel Kit's NEEDS word for word, from the worker's status), `why` (for `stopped`: `usage`, `killed`, `time`, `unfinished`; for `failed`: `unsafe`, `own` (one of Studio's own names was in the project and not Studio's: below), `error`, `no claude`, `no settings`; a project with no slug is refused, `no slug`, and nothing is written) and `queuedAt`. `statusOf` reads a `queued` or `working` state whose `pid` is not running as `stopped` at its step, `why: "died"`. And her chat's own (plan Task 11): `minutesLeft` (the worker's guess while it works, copied from its status, taken away when the run ends), `approved` (`{at}`, written by `reelkit go`, the only way `finalize` runs; taken away by a revise, whose next storyboard waits for her go again) and `notesUsed` (how many of `storyboard/notes.json`'s notes a revise has taken; the next revise takes those after). `go`, `revise` and `resume` mark the project `queued` with the pid of the run they started before her chat is answered; that run takes the mark for its own (`runJob`, by its pid). And the render's (plan Task 14, `reel-kit-render.js`): `fingerprint` (`sha256-<64 hex>`, `reel-kit-project.js` `compositionFingerprint`, Decision 6: the SHA-256 of the sorted manifest of `<sha256>  <path>\n` lines of `edit.py` and every file under `fx/`, `cards/` and `public/`, leaving out `public/`'s `snapshots/`, `renders/`, `.hyperframes/`, `CLAUDE.md` and `AGENTS.md` in any spelling the disk folds to them, and `.DS_Store` and `._*`; a link anywhere in it refuses it), written when finalize ends `ready` (one that can't be made fails it, `why: "fingerprint"`) and never by a render: the render runs in a copy of the project and never writes the project, so an edit she saves in the app while it renders stays hers, and her next render is refused as changed in HyperFrames rather than built over it; a render is refused while it no longer matches, and `reelkit status` says so for a ready edit; `rendering` (`{pid, start, at}`, marked by `reelkit render` with the pid of the run it started and its start, taken by that run, taken away when it ends; `status` says a ready edit is being rendered, and `revise` is refused, while that pid runs and is the same process, `reel-kit-render.js` `renderingBy`); `lastRender` (`{at, name, qa: "passed"|"failed"|"", why: ""|"qa"|"error"|"time"|"odd"|"record"|"own"}`); and `renders` (`[{name, file, phone, at}]`, each render kept: `name` `<slug>-v<n>`, `file` and `phone` paths from the project). A pass sets `state` `rendered`, only while the edit is still `ready` (a job that took it while it rendered keeps its own state, and nothing is kept as an export); a render that left one of Studio's own names in the project sets `state` `failed`, `why: "own"`, as the worker's run does; any other failure leaves it as it is. As a courtesy, a render is not started while anything but Studio holds the project open (lsof; its line says to close it in HyperFrames first): the app may hold no file open, so the copy, not this look, is what keeps her edits.
- `renders/<slug>-v<n>.mp4` and `renders/<slug>-v<n>-phone.mp4`: Reel Kit's render and its phone copy (its `render.py` and `qa.py`, run by Studio with `--no-deliver`, never without), `n` one after the highest render the project lists or holds, so none is written over. Made in the render's copy and brought in by renaming, only when it ended 0 and is a plain file straight in the copy's own `renders/`, never over a file there; nothing comes back from a failed render.
- `~/BRIMM Video Work/.reel-kit/tmp/<slug>.render/project/` (`reel-kit-render.js` `copyProject`, made fresh for each render and taken away when it ends): the render's copy of the project, by APFS cloning (a plain copy where the disk can't), links copied as links, without the project's `renders/` (an empty one is made) or any of Studio's own names (`OWN_NAMES`, folded as the disk folds names, at any depth). Reel Kit's `render.py` runs on it; what it makes there other than the render (its build's `public/`, records of its own, snapshots) goes with it. It is looked over for Studio's own names before and after (`sweepProject`): a find before keeps it from rendering, after fails the render, `why: "own"`.
- `public/renders/<entry name>_<YYYY-MM-DD>_<HH-MM-SS>.meta.json` (`reel-kit-render.js` `writeMeta`, Decision 7; written whole, only into a `public/` and `renders/` that are the project's own folders, never through a link, never over one there): `{status: "complete", exportedTo: <the render's whole path in renders/>, settings: {format: "mp4", resolution: "1080x1920"}}`, the time when the render began, in the Mac's zone. `exportedTo` is only ever a plain file straight in the project's own `renders/`, that folder no link and the file's real path inside it (`renderInProject`); a render anywhere else is refused, and kept as no export. A record the render makes for itself (HyperFrames' own render may, or the model-written `edit.py`) is in its copy, never the project, and goes with the copy. It is the record an app export leaves, so `exports.js` `metaNameOf` and `metaOf` read it; `projectDirOf` names `public/` as a Reel Kit edit's place for them (Task 15 wires it in). Written only when QA passed.
- Beside the source: nothing. A render never delivers (`--no-deliver`), and after each one `sweepCopies` moves to the Trash (`/usr/bin/trash`, never a delete) every plain file in `source/` named `<Title> v<n>.mp4` or `<Title> v<n> (phone).mp4`, the title as Reel Kit's deliver names them; a link or a folder of that name is left and named in the log, and a `source/` that is a link is never looked in.
- `work/worker-status.json` (the worker's own, written by it at each step, WORKER.md): `{step, needs: [{beat, text}], minutesLeft?}` (`minutesLeft` its guess, a whole number from 1 to 600, which `reelkit status` says as Reel Kit's own guess). Read by `readWorkerStatus` the safe way (no link, no pipe, at most 64 KB), its step one of the job's and at most 40 NEEDS of at most 1,000 characters; anything else is ignored with a line in the log. Taken away before each run.
- `from-you/` (when there): what she gives the edit (WORKER.md: the only source material it uses). `reelkit status` makes it (never through a link) and opens it in Finder when the edit has NEEDS.
- `storyboard/notes.json`: Reel Kit's own notes file, `[{beat, text, at}]`: `beat` is `p<digits>` or `all`, `text` her note as she said it (at most 4,000 characters, Reel Kit's `serve.py` cap), `at` an ISO time. `reelkit note` adds one (never a note on all of it that says only go, in any case: only `reelkit go` approves), and `reelkit go` the note `{beat: "all", text: "go"}`: read with no link followed and at most 4 MB, written whole (a file of its own beside it, then renamed), only into a `storyboard/` that is a folder and not a link; notes that can't be read whole are never written over. Notes are data.
- `storyboard/index.html`, `storyboard/files.json` and the files it names (Reel Kit's `storyboard.py`: `frames/*.jpg`, `fonts/*`): the worker's, read by `reelkit storyboard` only to stage them (below), never published from the project itself.
- `<episode work folder>/reel-kit-<main|reel-n>.start.json` (`reel-kit-commands.js`, written whole): `{key, why, at}`, left by a start whose project was never made (`why` the line she reads, from `scaffold`, or "Ask Jason."), which `reelkit status` says until the next start of that part takes it away.
- What Reel Kit's `new.py` makes there (through the link below): `assets/`, `audio/`, `cards/`, `fx/`, `public/cards/`, `public/media/`, `renders/`, `storyboard/`, `work/`, `style/` (copied from `.reel-kit/style/`, which `syncPack` builds from her pack first), and `edit.py` (`TITLE` her Reel's title word for word, `STYLE` the mode, `SRC` the path of `source/clip.mp4`). A title with a double quote, a backslash or a control character is refused first, as `edit.py` holds it between double quotes.
- `~/BRIMM Video Work/.reel-kit/projects/<slug>` (`linkProject`, Decision 2, made before the project folder): a symbolic link to the project folder, `<episode id's last 6>-<main|reel-n>-v<n>` (`slugOf`), where Reel Kit looks for it. It is never made over anything else (a folder, a file, a link elsewhere), nor when `projects` itself is a file or a link.
- The tests' stand-in for Reel Kit's scripts is `tool/tests/stand-ins/reel-kit.mjs` (Decision 8: `new.py`, `render.py`, `qa.py`), its starter `edit.py` `tool/tests/fixtures/reel-kit-1.2.0/project/edit.py`; `tool/tests/stand-ins/sandbox-exec.mjs` stands in for `/usr/bin/sandbox-exec`.

## Staged storyboards and their registry (plan Task 12)

- `~/BRIMM Video Studio/Storyboards/<slug>/v<n>/` (`storyboard-opening.js` `stagePage`, run by `reelkit storyboard`): a copy of a Reel Kit project's `storyboard/` (or a style board), one folder per version, `<slug>` the edit's slug, in her folder because the Artifact tool takes files only under the chat's working folder. Only `index.html` and the files its `files.json` names are copied: each name of at most four parts, each part starting with a letter, a digit or `_` (never a dot), of a picture, font, video, sound, style or script type (never `.md`, `.json` or `.html`), no two folding to one name; each file a plain file reached by no link, looked at before it is opened and after, at most 15 MB (the page 16 MB), at most 254 files and 64 MB in all. Written with `wx`, mode 644; a version folder that is there already is never written into (the next free one is taken).
