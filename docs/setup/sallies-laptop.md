# Setting up Sallie's laptop

For Jason, with Sallie, in person or by screen share. About two hours. Each step says what to check. Nothing here is done without your yes; the installer runs with `--print` first.

## Morning checks (only the laptop can answer these)

Write each answer down; tell the design session if one is a surprise.

1. **macOS version:** Apple menu > About This Mac. Final Cut Pro 12.4 needs macOS 26.6 or later (its LSMinimumSystemVersion); on anything older the App Store gives 12.3. Update macOS first (System Settings > General > Software Update; about an hour with restarts, so start it first), ideally to 27 like the Mac Studio, then App Store > Updates. That upgrade is your and Sallie's decision: if you decide to stay on 12.3 today, step 10 is then the first check that 12.3 opens brimm-video's timelines (relative paths, and one Reel push for the upright format), and the two Macs' Final Cut versions differ until you bring them together.
2. **Free disk space:** Apple menu > About This Mac > More Info > Storage. An episode needs its raw video (about 2 GB an hour on Zoom) plus its library and renders; keep 100 GB free.
3. **Her Claude plan:** after step 6 below, `claude auth status --text` shows it. It must include Claude Code (Pro or Max).
4. **Final Cut Pro on her Apple ID:** bought, or shared with her by Family Sharing from yours. Open it once and note the version (Final Cut Pro > About).
5. **Her Dropbox:** signed in to the account The BRIMM DB is shared with; note the path to `The BRIMM DB/BRIMM Video` in Finder (Control-click the folder with Option held, Copy as Pathname).
6. **Her macOS user name and her `~/Movies`:** in Terminal, `whoami` and `ls -l ~ | grep Movies`. If Movies is a link into Dropbox, say so (Final Cut templates go there later).
7. **Her account is an administrator:** System Settings > Users & Groups shows Admin under her name. Homebrew and Xcode's tools need it; she types her own password each time.

## Steps

1. **Xcode's command line tools:** in Terminal, `xcode-select -p`. If it is not there: `xcode-select --install`, and click Install.
2. **Homebrew:** `brew --version`. If not there, she runs the command from https://brew.sh in Terminal and types her own password when it asks; then she runs the commands it prints under "Next steps".
3. **The deploy key** (read-only access to the code; the project's one secret, only on her laptop):
   - `ssh-keygen -t ed25519 -f ~/.ssh/brimm_video_deploy -N "" -C "brimm-video read-only, Sallie's laptop"`
   - `cat ~/.ssh/brimm_video_deploy.pub` and send yourself the one line it prints (this half is not secret).
   - On GitHub: jogden12/brimm-video > Settings > Deploy keys > Add deploy key. Title "Sallie's laptop", paste the line, leave "Allow write access" OFF, Add key.
   - Add the host to `~/.ssh/config`, in Terminal (it makes the file if it is not there):
     ```
     mkdir -p ~/.ssh && cat >> ~/.ssh/config <<'EOF'
     Host github-brimm-video
       HostName github.com
       User git
       IdentityFile ~/.ssh/brimm_video_deploy
       IdentitiesOnly yes
     EOF
     ```
   - `ssh -T git@github-brimm-video`: the first time it asks whether to continue connecting; check the fingerprint is `SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU` (GitHub's published ED25519 key) and type `yes`. It should then say "Hi jogden12/brimm-video! You've successfully authenticated, but GitHub does not provide shell access."
4. **The code:** `mkdir -p ~/"Claude Code" && git clone git@github-brimm-video:jogden12/brimm-video.git ~/"Claude Code/BRIMM video"`. It stays on `main`; nobody edits it on her laptop.
5. **Final Cut Pro settings** (Final Cut Pro > Settings): Import > Files: **Leave files in place**. Playback: background rendering **off**. Destinations: add **Export File**, rename it **BRIMM final**, Format **Video and Audio**, Video Codec **H.264**, Resolution **Same as Source**, Action **Save Only**; Control-click it > **Make Default**. Leave library backups as they are. Turn the App Store's automatic updates off: App Store > Settings…, Automatic Updates off (or System Settings > General > Software Update, the (i) beside Automatic Updates, "Install application updates from the App Store" off). It is one switch for every App Store app: she updates other apps from the App Store's Updates list; you update Final Cut, on both Macs together.
6. **Claude:** install the Claude app and sign in. In Terminal, `claude --version`; if it is not there, install Claude Code as Anthropic's page says. Then `claude auth login`: she signs in to her own account in the browser (signing in to the app does not sign in the `claude` command). `claude auth status --text` must then show her signed in, and her plan (morning check 3).
7. **The installer, printed first:** `cd ~/"Claude Code/BRIMM video/tool" && ./install.sh --print --machine "Sallie's laptop" "<path to The BRIMM DB/BRIMM Video>"`. Read every line with her: the drop folder, the programs Homebrew will install (node, ffmpeg, whisper-cpp), the model (about 1.6 GB), Final Cut, Claude's sign-in, her folder for Claude. If it says Claude Code's version is older than 2.1.295, run `claude update` first and print again: on an older one her folder's guard could let a call through, and the install does not write her folder. Then, with your yes, run it again without `--print`. It downloads and installs; it asks "Go ahead?". When it has finished, one of its last lines must begin "From the background job:"; if none does, the setup stopped before its check of Claude, so note what it said last and tell the design session. Then `ls ~/Library/LaunchAgents/com.thebrimm.claude-check.plist` must say "No such file or directory": that file is the setup's one-shot check of Claude, which a setup cut short can leave behind, and launchd then runs it at every login. If the file is there, with your yes, either run the setup again to its end (its `--print` names the file first, and the setup takes it away before anything else), or take that one agent away alone: `launchctl bootout gui/$(id -u)/com.thebrimm.claude-check; rm ~/Library/LaunchAgents/com.thebrimm.claude-check.plist`. It is not `./install.sh --remove`, which also stops the import's own agent, com.thebrimm.unedited.
8. **Dropbox:** in Finder, Control-click `BRIMM Video/Unedited Video/Sallie's laptop` and choose Make available offline. macOS may ask whether node may read the Dropbox folder: Allow.
9. **Check that her Claude folder only runs BRIMM Video:** open the Claude app's Code tab on `~/BRIMM Video Studio` and accept the folder's trust question. First type `/status` and read the Claude Code row: it must be 2.1.295 or later (the Code tab runs its own copy, which can differ from `claude --version` in Terminal); if it is older, choose Claude > Check for Updates, then start a new session. If Claude Code shows a settings error or a warning about a deny rule at start, note it and tell the design session. In the mode selector, check that Auto and Bypass permissions are not offered, then pick Manual. Ask each of these, one at a time, and check that no approval card ever appears: "What's waiting?" (it lists the episodes); ``Open the episode called Charge $99 `now` \ok`` (there is no such episode, so nothing is opened or written; read it as below); "Run the date command." (refused); "Read the file /etc/hosts." (refused: it is outside her folder); "Read <an episode's transcript, by its full Dropbox path>." (refused); "Show the episodes and the date in one command." (refused); "Run date in my terminal panel", "Watch the import log in the background", "Publish this as a page", "Check my email" and "Take a screenshot" (each refused, or no such tool). Once videos are waiting, "What's waiting?" also shows her question card about a video ("What is …?" and "Is it a private session …?"), which is not an approval card: dismiss it by answering Other, "not now", which runs nothing; an approval card, one asking to allow a tool, is still a stop-and-tell. The Charge $99 question tries a title's words with a $ sign, a backtick and a backslash, which go to brimm-video in single quotes (as words with a straight double quote do too). Claude's answer does not show whether they arrived as you typed them: it may say it in its own words, or show the backticks as formatting. So read the command itself: click the row of the command Claude ran, above its answer, to open it (or set the session's Transcript view to Verbose, in the menu of its title bar). The command must end ``open 'Charge $99 `now` \ok'``, and what brimm-video printed under it must begin ``No episode fits "Charge $99 `now` \ok".``, each with every sign as you typed it, none added or dropped. The command ends with exit code 1, because no episode fits, and the row may show that as an error: that is not a refusal, which would say "In this folder Claude runs only brimm-video's own commands". Read the first line brimm-video printed, under any exit-code line. If it printed "There are no episodes yet.", ask it again after step 10. Ask the date and /etc/hosts questions again in Accept edits and in Plan, and the Charge $99 one again in Accept edits, read the same way. Never use the deploy key, or any other secret, as the file to try. If anything but "What's waiting?" and the Charge $99 question is allowed, if anything asks for approval, or if the Charge $99 command is refused, or it or what brimm-video printed adds, drops or changes a sign, stop and tell the design session. Make this check again after any pull that changes her folder's lock (see "Jason has a newer brimm-video", below).
10. **The first real run:** drop a short recording (a minute or two) into her drop folder, keep the lid open, and watch the panel. When it says Ready, first check that Claude was asked from the background job: in her Claude folder, "show me Claude's notes" must give notes, and the cut plan must not open by saying Claude could not be asked (if either fails, read ~/Library/Logs/brimm-video.log). Then, in her Claude folder: "open <its name>", "show it in Final Cut" (Final Cut asks once to be allowed; Allow), trim something by hand, Share it (the first save dialog will not be in From Final Cut yet: press Command-Shift-G, type `~/BRIMM Video Work/From Final Cut`, Return, and drag that folder into the dialog's sidebar), Export XML of the same project (check its dialog is in From Final Cut too), "finish the episode", and drop the hand-off on the BRIMM Ops page. Note how long the import took (the M4's speed) and the episode folder's size.
11. **The Mac Studio on the same brimm-video:** until its checkout has phase 1b, its `open` writes no claim and its writers ignore hers. On the Mac Studio, with no import running (the panel says nothing is in progress): `git -C ~/"Claude Code/BRIMM video" pull` (it stays on `main`), then `cd ~/"Claude Code/BRIMM video/tool" && node --test` (all pass, 0 fail). If one fails, run that file again on its own, for example `node --test tests/guard.test.js`: three tests sometimes fail only when the whole suite runs at once (guard.test.js's SIGINT and SIGTERM tests, and dropbox.test.js's "9. makes a clone"). Then look for a check agent a setup cut short left behind, as at the end of step 7: a pull runs no setup, so nothing else takes one away. `ls ~/Library/LaunchAgents/com.thebrimm.claude-check.plist` must say "No such file or directory". If the file is there, with your yes, take that one agent away alone: `launchctl bootout gui/$(id -u)/com.thebrimm.claude-check; rm ~/Library/LaunchAgents/com.thebrimm.claude-check.plist`. It is not `./install.sh --remove`, which also stops the import's own agent. Then open a test episode there and check that "what's waiting?" shows `Editing: Mac Studio`.
12. **The two Macs:** on the Mac Studio, open an episode; on her laptop, open the same one: hers must say the Mac Studio has it. Then "hand it to Jason" on one, and open it on the other.
13. **A conflict, on purpose** (to learn Dropbox's naming): pick an episode nobody has open. Pause Dropbox on both Macs (its menu-bar icon > Pause syncing; on the laptop, turning Wi-Fi off also works); on the Mac Studio say "call it Test A", on her laptop "call it Test B"; resume Dropbox on both and wait. Note the conflicted copy's exact file name in the episode's `record/` folder, check that "what's waiting?" names the conflict, and that "sort out the conflict" finds it. If either does not, tell the design session the exact name: it goes into `CONFLICT_FORMS` in `tool/episode.js`, the one list that finding the copies, naming the file each is a copy of and naming the Mac it came from are all built from, and a row of its test.

## If something goes wrong

- The import stopped: "try it again" in her Claude folder; the log is `~/Library/Logs/brimm-video.log`.
- "Jason has a newer brimm-video": in Terminal, `cd ~/"Claude Code/BRIMM video" && git pull` (only when no import is running), and on the Mac Studio too. A pull never rewrites a folder for Claude (`~/BRIMM Video Studio`), so on each Mac that has one, her laptop's and the Mac Studio's when the installer made one, also run the command `behind` names next (below), then start a new session in that folder. When the pull changes her folder's lock (the files `git pull` lists include `tool/studio.js` or one in `tool/studio/`, as the pull that lets words through in single quotes does), the folder's guard changes at once, since it is read from the checkout at every call, but not its settings and skill, which are copies: so write the folder again in that same sitting, on every Mac with one, and make step 9's check again. Then, on each Mac, look for a check agent a setup cut short left behind (step 7): a pull runs no setup, so it does not take one away, and launchd runs one left by an older installer at every login (from this version on it asks Claude nothing, but take it away). `ls ~/Library/LaunchAgents/com.thebrimm.claude-check.plist` must say "No such file or directory". If the file is there, with your yes, take that one agent away alone: `launchctl bootout gui/$(id -u)/com.thebrimm.claude-check; rm ~/Library/LaunchAgents/com.thebrimm.claude-check.plist`. It is not `./install.sh --remove`, which also stops the import's own agent, com.thebrimm.unedited.
- "Her folder for Claude is out of date" (what `behind` says when the checkout would write the folder otherwise): in Terminal, `cd ~/"Claude Code/BRIMM video" && node tool/settings.js studio --node <node>`, with the node `behind` names, which is the one the folder's settings already use (usually `/opt/homebrew/bin/node`; a node that is not there would stop every command in her folder). Then start a new session in her Claude folder.
- Claude says a conflict needs Jason: stop there and keep nothing. Jason sorts it out with Claude on the Mac Studio. It is said when one Mac's change reached the other only after that Mac had changed the episode more than once meanwhile, so keeping either side could lose a change; when Dropbox kept a copy that resolve cannot sort out; when resolve itself could not finish; and when, after a keep, a file is still not as the record lists it once Dropbox has finished (the keep is made by then: stop there). It need not come from both Macs changing one episode at nearly the same moment: the changes can be hours apart, as when one Mac was offline or had Dropbox paused.
- A title or name with a $ sign, a backtick, a backslash or a straight double quote (as in a quoted phrase) is refused: her folder's lock takes such words in single quotes, and Claude puts them so once her folder has been written since the pull that brought that change (above), since its skill then says so. Words that hold both one of those signs and an apostrophe cannot be passed at all: say them another way, "99 dollars", not "$99".
- Revoking the key (laptop lost, or no longer needed): GitHub > jogden12/brimm-video > Settings > Deploy keys > Delete.
